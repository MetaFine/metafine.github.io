Recording demonstrations

record.py is the single entrypoint for generating expert demonstrations. It runs an MP-based solver (motion planning + scripted skill controllers) inside the SAPIEN simulator, then dumps successful episodes as HDF5 trajectories paired with video. Two modes: single-skill for atomic-skill data, --task-graph for full compositional tasks.

Single-skill mode

Use this mode when you want to collect demos for one atomic skill against one asset — typical for pre-training or skill-level ablations. Supply --task (one of the 21 skill names) and --object (the asset id). The expert MP-solver figures out the correct part to act on by querying the asset's capabilities.json. 

# Record 20 grasps on asset 100221, save to demos/grasp_part/100221/
$ python record.py --task grasp_part --object 100221 --trials 20

# Headed mode + custom seed for reproducibility
$ python record.py --task press --object 103594 \
    --trials 10 --seed 42 --render-mode human

--task-graph mode

For compositional tasks, point --task-graph at a YAML chain. Each node is a skill call against a named asset/part; predicate goals are evaluated after the final node to decide if the episode counts as a success. Only successful trajectories are written to disk. 

# Record 30 successful long-horizon "open lid → rotate inner part" demos
$ python record.py --task-graph configs/lid_then_rotate.yaml --trials 30

# Custom output dir + bumped MP horizon for longer chains
$ python record.py --task-graph configs/peg_in_hole.yaml \
    --trials 50 --max-steps 600 --output demos/peg_in_hole_v2/

How the expert solver works

Each atomic skill is paired with a scripted controller that uses motion planning for free-space motion and pre-programmed contact-phase trajectories for the engagement step. The solver is deterministic given a seed, so re-running with the same --seed reproduces the exact trajectory. Failure cases (e.g. unreachable target, IK fail) are silently retried until --trials successes are written.

Output layout

Each call produces a per-task / per-object folder under demos/:

demos/
  grasp_part/
    100221/
      ep_0.h5        # observation/action streams + final predicate state
      ep_0.mp4       # third-person rollout video
      ep_1.h5
      ep_1.mp4
      ...

Each ep_*.h5 is a flat HDF5 with arrays for observation.image, observation.state, action, plus a small attribute dict (task name, asset id, seed, skill phase boundaries). The MP4 is third-person at 30 FPS for visual QA — feed it to utils.replay when you need to walk the trajectory step-by-step.

Common flags

FlagDefaultNotes
--task—Atomic skill name (mutually exclusive with --task-graph)
--task-graph—Path to a task-graph YAML
--object—Asset id (required in single-skill mode)
--trials1Number of successful episodes to write
--seed0Base seed; per-episode seeds are seed + idx
--max-steps400Per-episode simulator step budget
--render-modergb_arrayhuman opens the SAPIEN viewer
--outputdemos/Override the output root
