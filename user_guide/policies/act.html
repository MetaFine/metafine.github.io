User Guide · Policies · ACT

ACT

ACT (Action Chunking Transformer) is MetaFine's lightest VLA reference. It predicts chunks of future actions in one shot — a simple, cheap baseline that's easy to overfit on small demonstration sets and a useful sanity check before reaching for π0 or OpenVLA.

Install

# From the MetaFine repo root
$ pip install -e core/policies/act

This pulls in the ACT-specific deps (torch, einops, the small CNN backbones) without touching the rest of your env.

Data

ACT consumes the LeRobot export directly. Convert your demos with utils.export_lerobot, then point the trainer at the resulting dataset. 

$ python -m utils.export_lerobot --demos demos/grasp_part/ \
    --output datasets/grasp_part_lerobot

Training

$ python core/policies/act/train.py \
    --dataset datasets/grasp_part_lerobot \
    --chunk-size 32 \
    --epochs 200 \
    --output checkpoints/act_grasp_part

The chunk size is ACT's central knob — large chunks reduce compounding error but make the policy slow to react to perception. 16–32 is a reasonable starting range for the fine-grained tasks MetaFine targets.

Diagnostic evaluation

$ python core/policies/act/evaluate.py \
    --task-graph configs/example_grasp_cap.yaml \
    --checkpoint checkpoints/act_grasp_part/last.ckpt \
    --episodes 30 \
    --dr-sweep standard --smoothness

ACT typically scores well on per-stage understanding for short chains, but the smoothness dimension surfaces its characteristic chunk-boundary jerks — a useful failure mode to watch.

Notes & caveats

  • Action space. Inherits the recording controller's action space (joint deltas or EEF pose); make sure the training dataset and the eval env match.
  • Temporal ensembling. ACT's optional temporal-ensembling at inference smooths out chunk transitions — see --temporal-agg.
  • Compute. Trains in hours on a single A100 for a few-thousand-demo dataset.
